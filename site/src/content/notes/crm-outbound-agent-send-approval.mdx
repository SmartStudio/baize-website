CRM 外联 Agent 发出的首封邮件、涉及价格或承诺的内容，以及给重点客户和在谈商机的邮件，都应先交人看。受合规约束的行业或地区、资料不足、跨负责人拼接上下文，也要暂停发送。范围明确的例行跟进，可以在规则检查通过后自动发。

人工审批放在发送之前。邮件已经进了客户收件箱，再让销售确认，只能处理后续问题。设计流程时就把查资料、起草、批准、发送拆开，发送工具检查到有效批准，或者确认符合自动发送规则，才执行。

## 首封触达：先看找谁、为什么找他

首封邮件先由负责这位客户的销售确认。审核时要看联系人是否对应、邮箱是否仍在使用、联系理由有没有资料支持，以及之前是否已经有人联系过。只有姓名和公司名，还不足以判断这封信现在适不适合发。

让 Agent 写个性化开场时，要把依据一起交出来。客户职位、过往沟通和需求记录各自来自哪里，是否过期，都要能查看。找不到依据的句子删掉，资料相互矛盾的地方交人确认。不要让它把猜测写成“了解到贵司正在采购”。

首封通过后，也只代表这次触达获准。以后更换联系人、转向新的需求或重新启动中断的沟通，都要重新判断。规则里写清哪些情况算新的触达，避免 Agent 把所有后续邮件都归为例行跟进。

同一批线索改用电话外呼时，哪几段交给 AI、哪几段留给真人，见 <NoteLink slug="ai-voice-outbound-vs-human-telesales">企业上 AI 外呼，同一批线索哪几段交给 AI、哪几段留给真人电销？</NoteLink>。

## 价格、折扣和承诺：销售看完还要有权批准

邮件涉及报价、优惠、交付日期、服务范围或效果承诺，就停在草稿。审核人要同时看到原始依据和邮件里的表述，确认引用的是适用版本，适用条件也没有被删掉。客户之前拿过优惠，不代表这次仍能沿用。

这类内容应转给有相应权限的人。负责联系客户的销售可以确认需求，超出其权限的折扣仍要交给授权负责人。系统检查批准人的角色，避免任何能打开页面的人都可以放行。

审核还要检查正文之外的附件和引用内容。正文没有写价格，附件里带着旧方案，也可能把旧条件发出去。审核人修改后，保存确认过的版本；Agent 再生成新版本，就重新走批准流程。

对外素材换成 AI 生成的视频广告时，品牌审核怎么过，见 <NoteLink slug="ai-video-ads-vs-brand-review">AI 视频广告：多发视频 vs 过得了品牌审</NoteLink>。

## 重点客户和在谈商机：先让当前负责人接手

CRM 外联 Agent 接到重点客户或正在谈的商机时，先把草稿交给当前负责人。对方可能刚在电话里提出新条件，销售也可能已经约好了下一步。CRM 里一条较早的备注，不能自动代替这些判断。

审批页面要显示客户归属、商机状态和最近沟通记录。归属缺失或多人负责时，先确定由谁处理，不要自动抄送一圈人当作已经协调。负责人变更后，待发送的邮件重新分配，旧负责人之前的批准是否仍适用，也要检查。

例行提醒如果要自动发，负责人应事先圈定适用场景和模板。客户已经回复、进入谈判或提出异议，就退出自动跟进。自动任务不能因为排进了队列，就无视后来的沟通变化。

## 行业、地区和上下文不确定：资料不齐就暂停

对受合规约束的行业和地区，由企业合规负责人先明确允许联系的条件、可用内容和需要保留的记录。Agent 根据已经配置的规则检查；无法识别客户所在地区，或无法确认联系条件时，进入人工处理。点一次批准不能代替这些前置条件。

上下文不足也要单独拦下。比如同名公司无法区分，近期记录相互冲突，或草稿用了另一个负责人名下的客户资料。审核人需要知道具体缺什么、冲突在哪里，才能决定补资料、删句子还是放弃这次发送。

不能只看 Agent 自己报的把握程度。系统还应检查资料是否缺失、是否过期、是否跨客户或跨归属取数。跨负责人引用资料时，先确认访问权限和使用范围，不能因为内容能被搜索到，就拿去写给客户。

客户资料里哪些字段 Agent 可以读、对话日志留多久，见 <NoteLink slug="personal-data-agent-minimization">个人信息 Agent：客户数据能用到哪一步？</NoteLink>。

## 审批页面：打开就能看清这封邮件

Salesforce 的外联销售 Agent Hunter 在官网说明，发外联邮件或方案这类会触达客户的动作，可以设置成先经销售批准，每个动作都有记录。

企业自己的审核页面也可以按一次具体发送来组织。草稿、收件人和客户信息放在一起，附件可直接检查；被拦原因写清楚是首封触达、涉及报价，还是上下文有冲突。用到的资料展示来源和时间，审核人能从句子回查依据。

批准、退回修改和取消发送要分开。记录谁在什么时候看过哪个版本、作出了什么决定，以及最终发送结果。退回时保留原因，便于区分资料错误、规则不适用和写法需要修改。

无人处理就继续等待，不能超时自动发送。待审时间过长，发送前重新检查客户状态。权限拆分可以参考 <NoteLink slug="agent-read-mail-vs-calendar-send">AI Agent 权限：读邮件行，发信要先批吗</NoteLink>，把起草和发送分别配置。

## 例行跟进自动发，也要检查频次和退订

已经获准的常规提醒，可以限定客户范围、模板、触发条件和发送时段后自动执行。只要加入了新报价、新承诺，或者客户状态发生变化，就转回人工处理。规则检查应放在真正发出的那一刻，覆盖排队期间发生的变化。

频次要按联系人汇总，连同不同销售和不同任务的待发邮件一起算。间隔和数量上限由企业按业务与适用要求设定，不能让每个 Agent 各算各的。客户回复、拒绝联系或退订后，取消后续待发任务，并在发送入口再次检查。

接口超时也不能直接重发。先查这封邮件是否已被发送服务接收，结果无法确认就交人处理，避免同一封邮件重复送达。记录里区分待发送、已提交和失败，别把“调用过工具”当作“客户已收到”。

上线前，用模拟客户测试首封、折扣、归属冲突、退订后仍有排队邮件等情况，检查哪些被拦、转给了谁、是否真的停止发送。测试安排可参考 <NoteLink slug="agent-sandbox-test-vs-prod-data">Agent 测试环境：接 CRM 前先用模拟数据？</NoteLink>。发现漏拦时，先暂停相关自动发送规则，核对已发记录和待发队列。

## CRM 外联 Agent：常见问题

### 每封跟进邮件都要销售手动确认吗？

范围固定、模板已确认、没有新增承诺的例行跟进，可以按规则自动发。客户回复、退订、商机状态变化或资料有冲突，就暂停。首封和敏感内容仍由对应负责人查看。

### 销售太忙，能让 Agent 自己批准吗？

需要人审的邮件不能交给同一个 Agent 自批。可以把待审任务转给有权限的替补人员，或者减少任务数量。没人接手就保留草稿，记录等待原因，暂不发送。

### 发信审批通过后，改过的邮件能直接发吗？

发信审批绑定的是确认过的收件人、正文和附件。任一项变化，都重新提交；客户状态或退订状态变化，也要重新检查。记录中保留批准版本与实际发送版本，方便核对。
