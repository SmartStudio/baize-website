员工搭建且跑着共享业务流程的自动化任务，其 Agent 归属要落在组织和流程负责人身上，不能挂在个人账号下。人员发生变动之前，先确认业务流程负责人、执行凭证、触发器、流程记忆以及连接的数据范围。岗位调整或员工退出时按清单交接：更换系统负责人、换掉个人凭证、检查定时任务与在途待办、清理私有偏好记忆；如果无人接手，先停用自动触发。

低代码平台让业务人员几分钟就能搭好自动化助手。一旦接进协同、工单流转或客户跟进，它就是公共流程的一部分。搭建人离开岗位时如果不做交接，后台配置很快就会变成隐患。

## 隐患根源：个人凭证与幽灵调用

很多自建 Agent 的问题出在凭证上：直接用搭建人个人的访问令牌或 OAuth 授权。

这种绑定方式在人员变动时会产生两类故障。一类是流程中断：员工离职后，企业通常在当天封禁其单点登录账号并注销访问令牌，绑定该凭证的 Agent 随即在下一次运行时报 401 错误，导致日常自动汇总、跟进提醒等流程停摆。

另一类更为隐蔽：员工转岗或账号清理延迟，后台任务继续以该员工的名义向外部发信、在内部修改状态。这造成了审计上的幽灵调用，一旦出错，系统日志记录的还是早已调离人员的名字。

Microsoft 2026 年 10 月 15 日在 Copilot Studio 博客发布了 agent accounts。这项机制让 Agent 使用经过批准的凭证和限定权限工作，不依赖个人用户的凭证。Microsoft 表示这类 Agent 属于组织，不随个人岗位或任期结束，管理员可以限定其访问范围并管理生命周期。同时推出的 business process memory 允许 Agent 跨轮次保留业务上下文，这些功能正通过 Frontier 计划逐步开放。

## 搭建时登记责任人与凭证，避免人员变动时抓瞎

搭建并发布共享 Agent 时，就登记业务流程负责人和运行凭证归属。流程负责人负责业务规则与异常兜底，运行凭证标明调用系统用的是个人令牌还是服务账号。生产环境责任人分工可参考 <NoteLink slug="agent-pilot-to-production-checklist">Agent 试点能跑通，扩到生产还缺哪几项？</NoteLink>，这里重点解决人员变动时的交接细节。

## 转岗与离职的差异处置：权限随岗位变，旧流程交出去

员工在内部转岗时，系统权限会随新岗位调整。如果保留旧部门 Agent 管理权，容易跨部门越权；权限被收窄则会导致 Agent 运行报错。转岗遵循流程随部门走的原则：员工调离前，把旧业务 Agent 控制权移交给继任者，移除原搭建人权限。

员工离职则是彻底注销身份：解除个人凭证，核查本地定时脚本，把共享业务任务移交给业务主管。

如果暂时无人接手，分三步处理：

第一步，先关掉定时触发器和 Webhook，保留提示词、工作流结构和历史日志；

第二步，通知原搭建人所在的部门或业务群，限期指定接手人；

第三步，到期仍没人认领、也没有下游业务反馈受影响，再归档并注销访问凭证。

员工转岗或离职前后找服务台 Agent 重置密码、解绑账号时，身份怎么核，见 <NoteLink slug="it-helpdesk-agent-password-reset">服务台 Agent 重置密码，员工身份怎么核？</NoteLink>。

## 凭证如何更换：从个人令牌平稳过渡到服务账号

别去找离职员工要个人密码或长期令牌来让它接着跑。

第一步，由 IT 管理员或云平台负责人创建独立的服务账号（Service Account）或托管身份凭证。

第二步，按最小权限原则，只给服务账号分配该任务需要的 API 权限和读写范围。第三方工具集成的权限审计可参考 <NoteLink slug="grok-bot-enterprise-access-audit">企业开通 Grok Bot，权限和审计要先定什么</NoteLink>。

第三步，在 Agent 平台把验证方式从个人 OAuth 切到服务账号，测试跑通后注销原员工的个人授权。

## 流程记忆与指令交接：保留业务上下文，清理私有偏好

保留公共资产：业务术语表、历史工单处理记录、标准答复模版和常见异常规则。这些资产能帮接手人了解决策依据。

清理私有设定：个人偏好提示词（例如模仿某人说话口吻）、指向个人网盘的路径、个人草稿箱联动规则和测试残留数据。接手人通读系统提示词，并在测试中验证输出符合预期。

## 继任人接手当天的四项核对

第一，用新配置的服务账号在测试环境试跑一次，验证各项工具调用与数据读写权限正常；

第二，调阅最近几次的历史运行记录与未结待办，排查有没有挂起的重试请求或未处理的报错；

第三，沿着流程确认下游到底有哪些业务群组或系统在使用它的输出，告知相关团队负责人已变更；

第四，把本次负责人变更的时间、交接人和新凭证记录写进系统配置日志，留下审计痕迹。

## 把 Agent 移交纳入人事退出清单

人事办理退出手续时，除了交接电脑和账号，还要核验自建 AI 资产。管理员或部门主管导出员工名下的 Agent 清单：个人自用的直接停用；承载部门流程的，确认交接人签字并完成凭证切换，才办结离职手续。

## Agent 归属：常见问题

### 个人日常办公用的小助手，员工离开时也需要逐一移交吗？

不需要移交。仅用于个人写邮件、润色周报或查资料的个人小助手，不涉及团队公共流程，也不写系统。员工离开时随个人账号注销或自行删除即可。

### 员工离职前不配合移交自建 Agent，管理员该如何接管？

企业平台都有管理员权限。员工如果不配合，管理员在后台把工作流所有者改派给部门主管，重置连接凭证并注销个人令牌，换成服务账号并核验提示词，即可重新接管。

### HR 如何把 Agent 纳入离职交接清单？

HR 可以在离职交接系统中新增「自动化资产」检查项。员工申请离职时，系统拉出名下的 Agent 清单；承载团队流程的，指定继任人并由业务主管在离职交接单上签字确认，才予放行。
