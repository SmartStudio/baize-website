企业让销售折扣 Agent 根据客户、产品与订购数量在报价里自动让价，价格底线和每一级的让价权限由销售负责人和财务一起定，写成规则交给 Agent。Agent 只在给定区间里自动让价，超出区间的生成让价申请交给有权限的人批，Agent 不能自己改底线。销售人员看过报价单再发给客户，事后定期复盘规则执行情况。

## 价格底线和让价区间谁来定

财务人员先核算各条产品线的直接成本与目标毛利，给出底线价格。销售负责人结合市场竞争程度和客户合作规模划分客户等级，给出不同层级的让价区间，双方核准后把规则写入报价系统。

比如面对长期采购的大客户，规则允许 Agent 在既定区间内自动微调；面对新增的普通客户，价格区间收窄，留出更厚的利润垫。Agent 面对所有询价都按这两套输入计算，不能私自调低底线，也不允许绕开预设的产品成本基准。

规则定下来以后，改动要销售负责人和财务一起批。哪类操作适合自动放行，见 <NoteLink slug="agent-tool-call-auto-approval-rules">Agent 工具调用自动审批：哪些放行、哪些拦下</NoteLink>。

## 区间内自动让价要带哪些依据

Agent 计算出让价幅度时，要在报价单旁附带让价理由与对比依据。销售人员不能只看到折后总价，还要看到 Agent 参考了哪份历史合同、当前采购量触发了哪档梯度，以及客户过往的成交价位。

比如 Agent 测算出让价幅度后，会在后台提取客户过往的成交记录，说明本次让价是为了配合大批量提货。业务员核对依据属实后再确认报价，防止 Agent 把低配产品的价格错配给高配型号。

报价单生成后不直接发送给客户。销售人员通读各项条件并确认交付期无误，再通过邮件或即时通讯工具发出；报价随邮件发出去前的人工审批，见 <NoteLink slug="crm-outbound-agent-send-approval">CRM 外联 Agent 发信前，哪几步要留人工审批</NoteLink>。

## 超出预设区间怎么逐级流转

遇到竞品降价或客户强力压价，计算出的让价幅度一旦跌破底线，Agent 立即停止自动出价。Agent 转为生成特价申请单，详细列出申请让价的具体幅度、业务员填写的丢单风险，以及对该单毛利的实际影响。

申请单按照公司制度逐级提交。比如让价幅度小的给大区经理批，跌破成本线的给销售负责人和财务负责人一起批，由具备审批权的人签字确认。

人工批复通过的特价只对当前这一张单据有效。Agent 按这次的批复出这一张报价单，不把批复结果当成新规则；后续该客户再有新订单，依然重新套用标准区间计算。

## 事后复盘哪些特价单常超权限

销售运营团队定期从报价系统拉取让价日志，统计哪些产品或客户总在触发超权限申请。长期频繁申请特殊让价，说明年初制定的基准线已经跟不上市场行情，需要人工重新介入评估。

比如某类特定物料因供应链成本下降，竞品普遍调低了报价，一线业务员被迫频繁提交特价申请。管理层根据复盘数据拉上财务重新测算成本，统一下调该产品的指导价与底线，更新规则库。

调整底线规则的过程全程留痕。报价系统记录每一次规则变动的发起人、审批人以及调整生效的批次；规则改动没经过两个人复核的，先不上线。

## 销售折扣 Agent：常见问题

### 客户拿竞争对手更低的价格来压，Agent 能不能跟？

Agent 不能跟进低于底线的价格。遇到外部低价竞争，Agent 只能在预设的底线区间内让步；比如客户要求的价格跌破底线，Agent 自动拦截并转成特价申请单，由业务负责人评估该客户的战略价值后再定夺。

### 底线规则定好之后还能临时调整吗？

底线规则允许调整，但需走特批流程并留存记录。业务中遇到原材料临时降价或紧急战略大单，由当初制定底线的销售负责人与财务主管共同签署特批单，在后台手动更新参数，变更过程存入日志。

### 折扣审批走得太慢，能不能让 Agent 直接批？

不能让 Agent 越权替代折扣审批。日常提速靠合理放宽区间让 Agent 自动让价，一旦突破底线涉及企业盈利边界，必须由承担经营责任的管理者签字把关，Agent 只负责备齐数据。
