财务部门引入开票 Agent 对接业务系统，算法自动核验合同明细、订单金额与客户开票抬头，批量生成数电票。开票环节出现项目分类错误、税率选错或金额偏差时，算法无法越过财务内控单方完成红冲。开票 Agent 负责拉取差异数据并形成红冲审批单，由经办会计与财务主管逐级核准后进入税务系统开具。

## 开票前三单交叉比对，实人认证后出票

业务部门提交发货结算单，开票 Agent 读取销售合同台账中的买方名称、纳税人识别号与开户行账号。算法逐行校验销售明细中的货物规格、数量与合同单价，发现金额对不上时自动拦截并挂起工单。

对账到付款哪几道关不能省，见 <NoteLink slug="ap-invoice-agent-payment-control">应付账款 Agent 从对账做到付款，中间哪几道关不能省</NoteLink>。开票 Agent 完成三单匹配后，将开票请求推送至开票终端。税务系统要求开票人员完成实人认证，经办会计确认待开清单无误后通过实人认证出票。算法只执行数据比对与填报草拟，税务身份认证与最终点击动作留在财务人员手中。

## 发现错漏先生成差异单，财务审批后提冲红

客户收到电子发票后提出服务品名开错，开票 Agent 抓取原始合同明细做差异对比，生成一份红冲申请草稿。算法列出原蓝字发票号码、开错的品名税目、建议冲红金额以及对应的正确重开方案，附带业务部门的变更说明。

执行出错后怎么回滚，见 <NoteLink slug="agent-rollback-and-accountability">Agent 已经执行出错了，怎么回滚、责任算谁的</NoteLink>。经办会计核对原票与业务合同，确认确实存在填开失误后，在财务管理系统中勾选冲红原因并提交主管复核。财务主管通过审批流签署同意意见后，系统才允许将红冲请求推向税务接口，防止程序擅自冲销已生效票据。

## 对方已确认的单据按税收公告流转确认单

客户财务已经在税务数字账户中把这张蓝字发票做了用途确认，开票 Agent 无法直接单方冲红。系统调用接口核对该发票在税务端的流转状态，提示当前发票已处于受票方确认流程中。

国家税务总局在 [关于推广应用全面数字化电子发票的公告](https://www.gz.gov.cn/ysgz/tzzc/ns/yszc/content/post_10028900.html) 中明确规定，数电发票开具需要通过实人认证等方式进行身份验证。蓝字数电发票开具后发生销售退回、开票有误、应税服务中止、销售折让等情形，按规定开具红字数电票。蓝字票未做用途确认及入账确认的，开票方发起红冲流程并直接开具红字数电票；已做用途确认或入账确认的，开票方或受票方都可以发起红冲流程，经对方确认《红字发票信息确认单》（以下简称确认单）后由开票方开具，确认单发起后七十二小时内未确认的自动作废；受票方已用于增值税申报抵扣的，要暂按确认单所列税额做进项税额转出。

财务人员依据公告要求在系统内生成确认单并发送给客户。开票 Agent 监控该确认单的流转节点，如果七十二小时内客户未确认导致单据失效，系统给经办会计发送预警消息，由业务员联系对方财务沟通后重新发起。对方完成确认后，经办会计再次完成实人认证，系统正式开出冲红单据。

## 原票冲红票与重开票绑定归档复盘

经办会计在税务系统完成冲红操作后，开票 Agent 自动把原蓝字发票号码、红字确认单号与新重开的发票编号关联存入台账。系统锁定三张票据的钩稽关系，并在财务软件中生成对应的记账凭证草稿。

财务主管调出本期冲红台账，排查开票 Agent 导致开错的具体根源。如果是因为客户纳税人识别号在合同库中未及时更新，管理员在客户主数据中锁定该字段并要求销售重新上传营业执照；如果是因为货物税目分类与税率映射规则存在歧义，税务专员调整算法的商品编码映射表，避免后续批次重复发生同类开票失误。

## 开票 Agent：常见问题

### 为什么不能让开票 Agent 自动完成全流程冲红？

冲红直接冲减企业当期销项税额，涉及增值税纳税申报与发票真实性。全流程自动化容易因数据抓取异常引发违规冲票风险。公告要求数电发票开具要通过实人认证等方式验证身份，这一步本来就落在开票人身上。

### 客户要求退货退款，冲红流程怎么走？

业务部门在供应链系统录入退货入库单，质检合格入库后，开票 Agent 调取退货数量与原出库单比对，生成部分冲红申请。经办会计核对退货单与原始发票，在税务系统发起红字流程，开具对应退货金额的冲红单据。

### 对方不确认，红字发票开不出来怎么办？

受票方在确认单发起后七十二小时内未确认的，该确认单在税务系统中自动作废，导致红字发票无法开具。经办人员需要联系对方财务核对明细与作废原因，双方沟通达成一致后，由开票方重新发起确认单流转。
