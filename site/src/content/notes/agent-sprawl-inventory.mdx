员工低代码自建放开后，做一次摸底的 Agent 盘点是扩量的前提。先建立 Agent 台账：每个 Agent 记清用途、搭建人、负责人、连接系统与数据、调用凭证、触发方式以及最近运行时间。摸清底数后，按接触数据与操作动作划分风险等级。长期无人使用、缺乏负责人或连接失效的任务，按规则停用归档。

企业内部自建工具普及得很快。西班牙电信运营商 Orange Spain 2026 年 10 月 8 日与 Google Cloud 宣布，员工在 Gemini Enterprise 的低代码框架上自建了 1,000 多个定制 AI Agent，覆盖人力资源、IT、销售和客服等业务。业务部门自己拉起流程解决日常杂务，避免 IT 成为瓶颈。但实例数量一旦上涨，全公司到底有多少自动化进程在跑、哪些在读写核心库、哪些早就无人维护，往往没人说得清。

## 先把台账字段定下来：七项信息记清谁在跑、谁负责

做 Agent 盘点时，台账记录七项基础信息：

用途说明：每天具体执行什么动作。比如“每周五提取客服工单摘要”，不能只填“工作助手”等泛词。

搭建人与现任负责人：发生配置漂移或业务纠纷时，由现任负责人定夺。

连接系统与数据范围：调用了哪些内部系统和表。查公共文档与读客户手机号，风险完全不同。

调用凭证归属：是用个人访问令牌、团队公共账号，还是专门的服务账号。用个人凭证跑后台任务的，台账里单独标出来。

触发方式：是手动点击、Webhook 事件推送，还是定时自启。定时和事件触发没有人工盯盘，更容易持续消耗资源。

最近一次运行时间：记录最后一次调用的时间。长期未调用的多半属于废弃产物。

风险评级：根据数据暴露面和操作影响打上等级标签，方便分类处置。

## 四个入口摸底：把藏在各处的 Agent 找出来

集中式平台管理后台：企业低代码平台通常提供管理员看板，可直接导出工作流清单、发布状态与调用日志。

连接器授权记录：很多自建 Agent 会打通 CRM、ERP 或邮箱。排查系统 OAuth 授权清单，能发现哪些个人账号在私下连系统。

API 凭证与访问密钥清单：排查网关和云平台的 API Key 生成记录。业务人员申请了数据库凭证且调用来自托管平台的，顺着密钥就能定位实例。

业务团队主动申报：通过问卷让各部门自查，补齐本地脚本与未挂定时器的轻量配置。对主动报备的配置给予正式支持。

在全面放开自建之前，限制初始使用范围可参考 <NoteLink slug="enterprise-ai-pilot-vs-accounts-for-all">企业 AI 试点为什么先从一个部门开始</NoteLink>。

## 按风险大小分级：看能碰什么数据、能做什么动作

低风险任务：只读公开信息或通用知识库，不向外部系统写入。这类 Agent 造成的破坏有限，台账登记后由业务部门自主维护。

中风险任务：能读取未脱敏销售记录或员工薪资等内部敏感数据，或生成待办与草稿。输出偏差容易导致信息泄露或流程返工，需指定负责人并记录查询范围。

高风险任务：拥有生产系统直接写入权限，比如改 CRM 状态、给客户发信、改库存乃至涉及资金。这类任务一旦失控会有直接损失，需纳入集中监控并配置人工审批。

## 找不到负责人的 Agent

CIO Dive 2026 年 10 月 16 日的报道提到，企业环境里大约四分之一的 AI Agent 在无人监控状态下运行。盘点里找不到负责人的，先停掉自动触发、保留配置，交接怎么做见<NoteLink slug="agent-owner-when-employee-leaves">员工离职或转岗后，他搭的 Agent 归谁接手</NoteLink>。

## 复核节奏与停用规则：长期未运行和失效连接定期清理

按团队定的周期跑一次全量复核，设定明确的清理规则：

活跃度检查：超过约定时间没被触发的 Agent，提醒负责人；一直不回应就转成休眠。

凭证与连接有效性：OAuth Token 过期或内部 API 持续报错的暂停调度，防止无效重试消耗资源。

负责人还在不在原岗位：人员变动了，就提醒部门指定新负责人。

## 盘点结果怎么用：把治理资源集中在两类任务上

优先治理两类任务：第一类是带外部写入和对外发送权限的高风险 Agent，检查是否配置了操作上限与回滚机制；第二类是接触核心敏感数据却使用个人凭证的中高风险任务，统一换成专用、最小权限的服务账号并收紧只读范围。

数量庞大的个人办公助手维持台账基本信息即可。在 Agent 盘点中筛出高风险任务后，接下来的防御性规则建设可参考 <NoteLink slug="agent-governance-before-scale">Agent 治理要赶在扩规模之前：推荐错了能不采纳，执行错了已经发生</NoteLink>。

## Agent 盘点：常见问题

### 业务部门自己搭的 Agent，IT 部门盘点时会遇到哪些阻力？

业务部门往往担心收紧权限或剥夺自由。低风险只读任务只登记不加审批，IT 帮业务管好凭证和监控，检查重点放在未授权写入与凭证泄露上。

### 盘点出来的存量 Agent，应该一次性全量整改还是分批处理？

存量任务分批处理。先锁定涉及生产写入和敏感数据的高风险 Agent，中风险任务给出整改期限并换掉共享凭证，低风险个人助手在日常复核中逐步登记。

### 企业怎样排查暗中运行的影子 Agent？

影子 Agent 多半绕开了集中平台，但访问内部系统会留下记录。可以查 SSO 日志里没登记的 AI 应用授权、API 网关上异常高频的个人 Token、邮件网关上没报备的自动转发规则。发现后先冻结凭证，再让使用人补登记。
