渠道返利 Agent 算的数如果经销商不认，先别改数。Agent 把这家经销商这一期的返利底稿和对方提出来的差异逐项对上，标出差异来自哪一处口径；属于我方数据错的，财务改数并留调整记录；属于条款理解不同的，由渠道经理和经销商按合同确认，必要时补签说明；特批和口头承诺补审批件后再算。最终返利对账单由商务和财务确认后才发，调整后的返利对账结果由双方签认。

## 差异通常出在哪几处口径

季度或年度返利对不上，多数是因为算账口径散在五个地方。不同部门各自按手头的表格和习惯算，到了对账节点就会撞出差额：

- **条款版本**：年度合同、补充协议、特批、邮件承诺并存，双方拿来算账的依据版本不同。
- **销量口径**：按发货、签收还是回款算，基数按含税还是未税算，合同规定和日常习惯没对齐。
- **退货冲减**：上期冲量达标的货在本期整批退回，上期已算的返利要不要追回、冲减算在哪一期。
- **结算主体**：集团下有多家法人，销量算给签单主体还是收货主体。
- **兑付记录**：冲抵下期货款、付现金还是给货，重复兑付和漏兑常藏在这里。

## 返利底稿要能复算到哪一步

规范做法是给每个经销商每个周期做一张可复算的返利底稿，写清条款版本、计算基数、销量事实（发货单、退货单、回款流水）、退货冲减（退货日期、冲减归属期、重算前后档位）以及兑付记录（方式、金额、凭证号、核销关系）。返利金额由固定规则计算，渠道返利 Agent 负责解释差异、补齐证据、组织例外确认。

核对按固定顺序走：先锁定经销商、结算主体和周期；取当期有效的条款版本和特批审批件；按条款口径取销量；退货按归属期冲减，跨期退货回溯重算上期档位；套条款算返利，记录公式版本和参与的单据；与已兑付记录比对，拦截重复兑付和漏兑；差异逐项解释，口径冲突和特批进例外确认队列。每一步的中间结果都留下来：到了哪一档、差多少到下一档、哪些单据参与合计。经销商质疑时双方看同一张底稿，不用各自重新导一遍表格。

## 经销商提异议后怎么逐项对

经销商对返利对账提出异议时，先核四样：条款版本、销量口径、退货冲减归属期、历史已兑付记录；多数异议都出在口径不同。渠道返利 Agent 把差异项放进例外确认队列，按规则分类处理：

- **跨期退货回溯**：跨期退货回溯重算上期档位，产生的差额在底稿上单独挂账。
- **主体与口径对齐**：签单主体和收货主体不一致的，按合同主体归集；合同写回款而习惯按发货的，以合同为准，把差异列出来交由商务确认。
- **特批与聊天承诺核查**：业务员口头或聊天里的承诺只当待核实线索，计算要落到有版本的条款上；没有系统内条款的特批，附审批件并经商务和财务双确认后入库。

## 改数、兑付和发对账单由谁批

返利金额确认、冲抵货款的释放、对外对账单的发送都是资金相关动作，由商务和财务按企业权限审批；Agent 的底稿和差异说明只是审批依据，不能代替审批本身，也不允许配置成「系统自动多退少补」。

兑付和冲抵货款同样是动钱的关卡，中间哪些审批与核销环节不能省，见 <NoteLink slug="ap-invoice-agent-payment-control">应付账款 Agent 从对账做到付款，中间哪几道关不能省</NoteLink>。给经销商的沟通草稿可以由 Agent 准备，发送前由商务确认；确属我方数据错的由财务改数并留调整记录，冲抵货款的建立核销关系防止重复支付，调整后的对账单经双方签认后归档。

## 渠道返利 Agent：常见问题

### 经销商集团下有多家法人拿货，销量算给谁？

按合同约定的主体归集。签单主体和收货主体不一致时，底稿以生效合同写明的结算主体为准汇总销量；如果要把合同外关联法人的提货量并入计算，需要补充协议或审批件，由商务和财务确认后再入库。

### 上期冲量达标的货在本期退回来，返利怎么扣？

退货按归属期冲减。遇到跨期退货时，按规则回溯重算上期档位，记录退货日期、冲减归属期以及重算前后的档位变化，差额挂账处理：预估返利还没兑付的，直接按重算结果出结算单；已经冲抵了货款的，差额转入下期核销。底稿附上对应的发货单与退货单明细。

### 返利对账时经销商拿出业务员的聊天承诺，算不算？

聊天承诺只当待核实线索，不能直接作为返利对账的计算依据。返利计算要落到有版本的条款或有审批依据的特批件上；没有系统内条款的特批，补齐审批件并经商务和财务双确认后，才入库参与重算。
