Codex 技能采用标准化目录打包流程规范与执行资源，在 Codex CLI、IDE 扩展及 ChatGPT 桌面端通用。安装可运行 `$skill-installer` 获取精选技能，也可在仓库 `.agents/skills` 或系统路径手动创建。调用支持输入 `$` 与 `/skills` 显式指定，也支持模型基于描述自动匹配触发。团队协作时，将技能目录提交至代码仓库受控管理；遇到不需要的技能，修改配置文件即可直接停用。

## 技能目录结构与各级扫描路径

每个技能是一个独立目录，遵循开放的 agent skills 标准。技能目录必须包含 `SKILL.md`，并在 frontmatter 中声明 `name` 与 `description`。目录内按需放置三类子目录与配置：执行脚本目录 `scripts/`、参考资料目录 `references/`、附加资源目录 `assets/`，以及高级配置文件 `agents/openai.yaml`。编写独立的 Codex Skill 时，原则是每个技能只聚焦一件具体任务；除非必须保证确定性执行或调用外部工具，优先编写纯说明而非脚本，并使用祈使句明确约束输入与输出。

新建技能有两种路径。在 Codex 里输入 `$skill-creator`，交互工具按用途、触发时机与脚本需求生成骨架，默认生成纯说明文件。用户也可以手动建立目录并写入 `SKILL.md`。

Codex 从以下四个层级读取技能：

- 仓库级：从当前工作目录 `$CWD/.agents/skills` 开始，逐级向上扫描父目录，直到仓库根目录 `$REPO_ROOT/.agents/skills`。
- 用户级：读取当前用户主目录下的 `$HOME/.agents/skills`。
- 管理员级：读取全局系统路径 `/etc/codex/skills`。
- 系统级：随 Codex 安装自带的内置技能，例如 `skill-creator` 与 `plan`。

所有层级均支持符号链接。如果不同层级存在同名技能，Codex 不合并配置，重名项都会出现在候选列表供选用。

## 运行 installer 安装精选技能与渐进加载

安装官方或精选技能，可以直接在 Codex CLI 或 IDE 会话中运行 `$skill-installer`。例如对接任务追踪系统，执行 `$skill-installer linear` 即可安装 `$linear` 技能。`$skill-installer` 也支持从指定外部仓库下载技能。官方将直接安装定位为本地配置与试用；向他人分发自建技能时，优先打包为插件。安装完成后 Codex 会自动检测变更，若未列出则重启生效。

为控制上下文消耗，Codex 采用渐进加载机制。会话启动时，模型仅读取每个技能的 `name`、`description` 与文件路径，不加载 `SKILL.md` 全文。只有当用户调用或模型决定选用时，Codex 才会读入完整正文。

默认状态下，技能描述列表最多占用模型上下文窗口的 2%；上下文未知时采用 8,000 字符限制。安装技能过多时，Codex 会先压缩 `description` 摘要；若超出过多，系统会省略部分技能并输出警告。若项目需要加载较多技能，可在配置文件中调整 `skills.max_context_tokens`，上限为 10,000 tokens。

## 显式符号调用与描述匹配隐式触发

Codex 技能调用区分为显式调用与隐式触发两条路径。

显式调用由用户主动发起。在 Codex CLI 或 IDE 扩展窗口中，输入 `/skills` 可调出技能列表；在输入框键入 `$` 字符可呼出联想菜单，例如键入 `$linear` 即可将流程绑定至当前任务。

隐式调用由模型自主判定。当输入自然语言需求时，Codex 会将任务内容与技能的 `description` 进行语义匹配，命中适用边界即自动载入流程。因此编写 `description` 必须简明，写清适用范围与边界，并将关键用途和触发词置于前列。编写完成的 Codex Skill 必须使用测试提示词检验，确认既定场景能正常触发，避免误触发。

精细控制可在技能目录下建立 `agents/openai.yaml`。该文件支持设定展示名称、图标、默认提示词、工具依赖（如 MCP 服务器）与调用策略。将 `policy.allow_implicit_invocation`（默认 true）设为 false 后，模型不再自动匹配该技能，仅保留 `$` 显式调用。

本文说明技能的安装与调用。关于主线程处理关键判断与子代理处理重复任务的分工，见 <NoteLink slug="codex-subagent-model-tiers">Codex 配 subagent：判断力留给主线程，重复交给便宜档</NoteLink>。

## 仓库版本受控与全局停用配置

团队管理技能的核心方式是将技能资产纳入代码版本控制。团队应当将通用流程与标准化技能存放在项目根目录的 `.agents/skills` 下，随代码提交至 Git 仓库。成员拉取仓库后，本地 Codex 即可自动识别工程规范，无需单独执行安装命令。

技能将重复操作固化为标准流程。将技能嵌入工程体系与门禁的方案，见 <NoteLink slug="codex-into-real-workflow">Codex 真正进入研发流程，需要解决哪些问题？</NoteLink>。

停用过期或冲突的技能无需删除文件。Codex 提供了就地停用机制：在用户主目录 `~/.codex/config.toml` 中增加 `[[skills.config]]` 项，将 `path` 指向目标技能的 `SKILL.md` 绝对路径，并将 `enabled` 设为 `false`。重启 Codex 后生效，本地文件仍然保留。

## Codex 技能：常见问题

### 新增或修改技能后没有生效怎么办？

Codex 支持文件系统变更自动检测。如果手动创建目录或修改 `SKILL.md` 后未在选择器中出现，重启当前的 Codex CLI 会话或 IDE 扩展窗口即可触发重新扫描。

### 技能数量过多导致上下文报警如何处理？

Codex 默认将技能说明开销限制在上下文窗口的 2% 以内（未知时按 8,000 字符限制）。超出后系统会截短描述或省略列表项并抛出警告。可在 `~/.codex/config.toml` 中配置 `skills.max_context_tokens` 扩大上限，该字段上限为 10,000 tokens。不常用的技能可以按上文在 `~/.codex/config.toml` 里停用。

### Codex Skill 和插件是什么关系？

Codex Skill 是流程逻辑的编写格式，插件（Plugin）是面向分发的打包容器。团队在本地设计和验证流程时，先以 Codex Skill 的形式组织 `SKILL.md`、脚本与依赖；当需要跨团队分发，或者提交至 ChatGPT 与 Codex 共享的插件目录时，再将技能与连接器（connectors）打包为插件发布。
