离职交接 Agent 负责按既有台账执行停权并反馈结果，漏了账号先看清单：清单里有而 Agent 没处理的，算流程和 IT；清单里没有的，算部门负责人没报全。工具只能收回登记在册的权限，员工自己注册的工具、绑在个人邮箱上的业务账号、共享账号密码和自建接口密钥，靠部门盘点补齐，把文件、邮件和 Agent 先转给接手人后再停账号。

## 离职交接 Agent 按什么清单收账号

参照美国国家标准与技术研究院的安全控制目录，人员离职时组织要在自己定的时限内停用系统访问，注销或收回凭证和身份认证手段，开展离职面谈，收回工牌、令牌、设备等安全相关物品，同时保留对其原来掌握的组织信息和系统的访问；目录还建议用自动通知和自动停用。企业上线离职交接 Agent，就是把自动通知与按单停用落到流程里。

可以配置成按 HR 系统里的离职日期，由 Agent 拉出该人名下的账号清单发起账号回收，覆盖统一身份账号、邮箱、业务系统、共享账号、云服务和 SaaS、接口密钥、门禁，逐个停用并回报结果。清单准不准看平时开号有没有登记；入职时怎么按岗位给权限和留底，见 <NoteLink slug="employee-onboarding-agent-account-access">入职开通 Agent 开账号，权限按岗位怎么给？</NoteLink>。前期开号走了统一台账，离职拉单才不会缺项。

## 清单外最容易漏的几类

实际出隐患的常是 IT 台账里查不到的权限。员工在岗时在统一身份体系外开的入口，Agent 按标准目录拉清单时扫不到。

业务部门在离职面谈与盘点时，要重点排查下面几类清单外的入口。

- **自行注册的外部工具**：员工用工作邮箱或个人手机号在外部协作、设计或数据工具注册的账号，没接统一身份认证，停掉主账号后外部登录依然有效。
- **个人邮箱绑定的业务账号**：早期开通的客户后台、渠道平台或第三方服务绑在个人邮箱和手机上，离职后验证码仍发往其私人设备。
- **共享账号的登录密码**：团队共用的运营号、店铺后台或测试账号，光把人移出协作群不够，不改密码照样能登录。
- **自建的接口密钥和定时任务**：员工用个人名义建的接口密钥和定时任务，停了人名账号后密钥可能还在后台继续调取数据。

## 谁确认、谁签字

账号回收跨人事节点、身份库、业务交接与独立后台，单靠 IT 或 HR 管不全所有入口。离职审批单要把各方签字动作拆清：HR 专员发起流程并确认最后工作日，日期改期立刻更新触发时间；IT 管理员负责统一身份和清单内账号，核验 Agent 回报的停用状态，收回工牌、令牌和设备。

部门负责人确认清单是否齐全，补报清单外的云服务、SaaS、共享账号与自建工具，并在停号前安排数据交接。没打通接口的独立系统，由各系统管理员收到派单后确认停用。顺序上先交接再停号，把离职人名下的文件、邮件转给接手人，他在岗时搭的 Agent 也一并移交；这类流程归谁接管，见 <NoteLink slug="agent-owner-when-employee-leaves">员工离职或转岗后，他搭的 Agent 归谁接手</NoteLink>。交接落定后，按时点停用登录权限并改掉共享账号密码。

## 漏了怎么查、怎么补登记

员工离职后要是发现某个业务系统还能登进去、某把接口密钥还在后台调用数据，或者外部 SaaS 平台账单还在按席位扣费，内审与 IT 安全可以顺着离职当天的账号回收记录查责任归属。核查时先调出离职审批单发起时各方签字确认过的那份权限清单，对照漏掉的这个账号当时有没有列在清单上。

如果该账号明明列在清单里，因为接口调用报错没有处理、手工派单超时没人跟进，或者共享账号只移出了成员却忘了改密码导致没收回来，责任算在流程配置和 IT 管理员或对应未执行的系统管理员头上，团队要立刻补做停权并修补失败告警。如果该账号压根不在当初确认的清单里，属于部门私下开通的工具、员工自建接口密钥或未报备的共享后台，责任算在用人部门负责人离职盘点时没报全。查实后除了马上注销凭证、收回访问，还要把这类新排查出来的系统和密钥补进企业统一权限登记表，后续同岗位人员入职开通或离职停权都按更新后的标准清单核对。

## 离职交接 Agent：常见问题

### 员工临时提出离职当天就走，来不及走完常规交接怎么办？

遇到当天离职或紧急解除劳动关系的情况，HR 确认最后工作时间后立即通知 IT 管理员先停掉统一身份账号、企业邮箱、门禁和核心业务系统访问，收回工牌与设备。离职人名下的邮件、云盘文档和自动化任务原地冻结保留，随后由部门负责人指定接手人，在 IT 协助下转移资料并补查清单外账号。

### 离职员工在职时跟同事共用的公共账号，把他移出协作名单就够了吗？

只移出协作名单不够。只要离职人员还知道公共账号的登录口令，离职后依然可能在外部直接输入密码登录。部门负责人要在离职清单里标出该员工接触过的全部共享账号，由系统管理员在最后工作日当天修改密码，并重新绑定在岗人员的身份认证手段。

### 账号回收是删除还是停用？

账号回收应先停用系统访问、注销或收回登录凭证，不要一上来直接删号。直接删除容易连带清空历史邮件、业务文档和审计日志；正确做法是先停掉本人登录权限、改掉共享账号密码，把文件和数据转给接手人，确保组织保留对其原来掌握的信息和系统的访问，之后再按企业保存制度定期清理。
