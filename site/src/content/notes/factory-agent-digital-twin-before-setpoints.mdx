数字孪生验证是工厂把 Agent 算出的速度、温度等新设定值写入产线前的一道前置检查。做完数字孪生验证且没有异常后，还要由工艺工程师核对结果、设备负责人批准，才执行设备参数下发，首次下发先在单台设备或单个班次试跑并备好回退值。

## 哪些参数要先过数字孪生

工厂里的 Agent 根据产线采集的数据算出新的速度、温度等设定值后，不直接写进现场控制器。企业事先列一份参数分级清单，写清楚哪些微调参数允许 Agent 在设定范围内自己调，哪些涉及工艺窗口、多机协同或安全联锁的改动要先走验证和审批。常驻 Agent 在产线日常能自己处理哪些事务，见 <NoteLink slug="factory-resident-agent-what-to-handle">工厂常驻 Agent 盯产线，哪些事能自己办？</NoteLink>。

全国标准信息公共服务平台上有信息技术 数字孪生 通用要求这份国家标准，已发布并实施。参考一家工业自动化厂商的公开入门手册，做虚拟调试要有真实机器的映像，这个映像叫机器的数字孪生；借助数字孪生，可以在虚拟环境里模拟和优化机器各部件的相互配合，不需要真实样机，虚拟调试可以降低出错风险，减少真实调试的工作量。凡是列入受控清单的设备参数下发，先在数字孪生里跑完模拟，再进入人工审批。

## 数字孪生验证看什么与说明不了什么

Agent 算出一组新参数后，工作流可以配置成先把这组参数送进对应的数字孪生环境运行。虚拟环境用同一组设定值跑完预定工况，重点检查以下几项指标：

- **生产节拍与动作配合**：看调整速度或行程后，上下游工位和机器各部件的相互配合有没有冲突或等待异常。
- **温度与工艺曲线**：看加热、冷却等设定值变化后，虚拟模型里的温度变化趋势是否越过设定的阈值。
- **联锁与报警状态**：看新参数会不会触发设备的安全联锁保护、急停条件或异常报警信号。

数字孪生验证通过，只说明这组参数在虚拟模型里运行没有报错。模型和真实设备之间有差别，刀具磨损、原料批次波动、现场温湿度变化以及机械老化，未必都反映在当前的虚拟映像里。不能因为模拟跑通了就跳过人工把关，上线前用模拟环境做验证的通用思路见 <NoteLink slug="agent-sandbox-test-vs-prod-data">Agent 测试环境：接 CRM 前先用模拟数据？</NoteLink>。

## 谁批准下发以及怎么试跑和回退

虚拟环境跑完并生成验证报告后，单据流转给工艺工程师。工艺工程师先看参数调整方向、模拟曲线和当班生产的品种要求是否匹配；确认合理后，转给设备负责人做最终批准，获批后才允许执行设备参数下发。

首次下发新参数时，不一下子铺到整条车间，先选一台设备或一个班次做小范围试跑。下发前，操作台把设备当前的原值和预设的回退值记下来。试跑期间如果现场出现异响、质量波动或报警，当班人员按设备负责人授权立即切回原值或回退值，不继续等待 Agent 重新计算。

## 模型维护与下发记录怎么留

数字孪生本身需要持续维护。现场设备做过机械改造、更换过关键零部件、调整过传感器位置或改过控制逻辑后，如果虚拟映像没有同步更新，跑出来的验证结果就不能信。设备团队在改造验收单里加上模型同步这一项，模型没更新完之前，相关工位暂停使用虚拟验证结论作为下发依据。

每一次参数调整都留存完整记录，字段包括工位编号、参数名称、调整前原值、Agent 建议新值、预设回退值、数字孪生验证结果与报告编号、工艺工程师审核意见、设备负责人批准姓名及下发时间。如果中途发生回退，回退触发原因、操作人和回退时间也一并记入同一条台账。

## 数字孪生验证：常见问题

### 没有数字孪生，Agent 算的参数还能用吗？

能用，但改变使用方式。还没有建好数字孪生的产线，不让 Agent 直接把参数写进设备控制器，只把 Agent 算出的新设定值当成调整建议推给工艺工程师。由工艺工程师结合经验人工评估，通过后由人工在单台设备上小范围试跑，确认稳定后再推广。

### 数字孪生验证通过了，还要人批吗？

要人批。数字孪生验证只反映参数在虚拟模型里的配合情况，模型和真实设备有差别，现场物料状态、机械磨损和环境变化无法靠模型完全替代。每次下发受控参数前，仍然要经工艺工程师核对、设备负责人批准。

### 设备参数下发后效果不好，怎么退回去？

每次执行设备参数下发前，台账里都会先记下调整前的原值和安全回退值。试运行期间一旦发现产品质量波动、节拍不稳或设备异常，由设备负责人决定回退，现场直接切回预先保存的原值或回退值；回退的原因、时间和批准人同样写进下发记录里。
