Agent 模型升级后如果线上流程结果变了，先去运行日志里确认实际服务的模型版本、提示词版本和工具定义版本，再用锁定用例集跑回归测试，对比新旧版本的工具调用结构与结果。红线用例被破直接不上线；调用结构变化交业务流程负责人逐条判断可不可以接受；上线决定由业务负责人和质量或风控签字，不由工程团队单方面拍板。线上已经执行出错后的回滚与追责归属事故处置，本篇只讲升级前后的行为差异怎么发现、怎么判以及谁拍板上线。

## 先确认是不是模型变了

Agent 的行为由三样东西一起决定：模型版本、提示词版本、工具定义版本。发布其中任何一样都等于一次上线。用浮动别名（只写模型家族名、不写具体日期版本）调用时，提供商可能在别名背后换成行为不同的新版本，仓库里一行代码没改，上周通过的评测针对的已经是另一个模型。

日常调用要固定到带日期的具体版本，并在每次运行的日志里记下实际服务的模型版本、提示词版本、工具定义版本；有的接口在响应里会返回实际服务的模型名，可以回读核对。提示词、模型、工具定义、检索设置任何一项变了都要重跑全套；检索分块方式变了、工具返回多了字段、对话历史变长，也会把 Agent 原来依赖的内容挤出视野，表现常常为不报错、回答照样流利但依据变了。

## 回归测试比什么

做 Agent 模型升级时，回归测试用一套锁定的用例集：代表性的常见请求、几个边界用例、至少一个测「永远不许破的规则」的用例（例如超出授权额度要转人）。用例集不要随手改，改了就和以前的结果没法比。换模型时只动模型这一个变量，提示词、工具定义、工具返回的测试数据、用例集、评判方式、推理参数都固定；不同模型接受的参数不一样，一侧设了的参数另一侧可能被忽略，跑之前要先核对。

升级前后重点比对调用结构与评判质量：

- **工具调用与参数**：核对有没有调用对的工具、参数对不对。
- **政策遵守与追问**：核对有没有遵守政策、缺信息时有没有追问；只比最终文本会把措辞不同但正确的结果判成失败。
- **用例与评判器自检**：新旧两边都失败的用例，先查测试本身有没有写坏；评判打分如果对所有答案都给满分，等于没测，拿一个已知为错的答案喂进去看分数会不会动。同一用例多跑几次以区分随机噪音，见 <NoteLink slug="agent-eval-suite-pass-rate-variance">Agent 评测怎么做：每个任务跑几次才算数</NoteLink>。

## 差异怎么分级、谁拍板

跑完锁定用例集后，不仅看整体通过与否，单项分数下滑也算回归。工程团队把新旧版本跑出来的所有差异汇总成清单，按风险性质分成三类，交由对应角色逐项审查确认：

- **硬性红线被破**：硬性红线没有容忍阈值，只要破一次就立刻转入人工审查，修复前不准上线。
- **调用结构变化**：调用工具的顺序、传入参数组织或缺信息时的追问行为变了，交由业务流程负责人逐条判断业务上可不可以接受。
- **风格与措辞变化**：工具调用和业务结论一致、仅文字表述风格变化的，作为判断题交由业务侧确认。

所有差异核对完成后，新版本能不能切流上线由业务负责人和质量或风控签字确认，工程团队负责提供评测对比报告，不单方面拍板切换。

## 新版本怎么分批上线

拿到业务与风控的签批后，新版本不能直接全量替换旧版本，要按四个阶段分批推向生产环境，同时隔离保护已经在跑的在途流程：

- **影子运行**：新旧版本并行跑真实流量，只对外输出旧版本结果，离线比对新旧行为差异。
- **小流量灰度**：优先在内部或低风险业务上切小流量试跑；从试点扩到生产还要核对哪些准备项，见 <NoteLink slug="agent-pilot-to-production-checklist">Agent 试点能跑通，扩到生产还缺哪几项？</NoteLink>。
- **看指标扩量与冻结**：评测和护栏指标保持正常才扩大流量，一出现回归就立刻冻结。
- **旧版保活与在途不换**：上一版本保持可调用；已经在跑的流程按它开始时打上的版本跑完，不中途换模型。

## Agent 模型升级：常见问题

### 仓库里一行代码没改，为什么 Agent 的行为突然变了？

常见原因是调用接口用了不带日期的浮动别名，提供商在别名背后换了新版本；或者检索分块方式变了、工具返回多了字段、对话历史变长，把 Agent 原来依赖的内容挤出了视野。排查时先看运行日志里记下的实际服务模型版本、提示词版本和工具定义版本。

### 升级切换时，正在跑的流程会中途换上新模型吗？

不会。上一版本在升级期间保持可调用，已经在跑的流程一律按它开始时打上的版本跑完，不中途换模型；新发起的流程才按灰度规则进入新版本。

### 厂商说新模型更强，回归测试还要跑全套吗？

要跑全套。新版本在某些公开基准上更好，在你的具体任务上可能更差，厂商的发布说明不能替代企业自己的评测。每次升级都要用锁定用例集重跑全套回归测试，并且红线用例一个不能破。
