## 试点环境与生产环境的五项翻转

试点项目能够顺利跑通，通常依赖五项先决条件：
1. 输入数据经过清洗，排除格式残缺与语义冲突；
2. 流程高度裁剪，仅保留顺畅的主干分支；
3. 使用人员限于研发或熟悉提示词的业务骨干；
4. 研发团队全程盯盘，遇异常可实时干预；
5. 系统仅开放只读权限，失误不产生财务损失或监管风险。

这五项前提到了生产都会翻转。真实业务数据充斥着非结构化噪声与历史遗留格式；Agent 需要跨越 CRM、ERP 等业务系统执行真实的写入动作；操作人员不再具备提示词调试经验；一旦产生错误调用，将直接带来资产损失与合规风险。

安永 2026 年 9 月的报告指出，企业用 AI 的速度跑在了运营模式前面。它认为，阻碍规模化的主要是流程没有重做、治理没有落到运行时，模型能不能用到通常不是最大卡点。

## Agent 扩产前要核验的五项清单

接主干业务之前，逐项核验下面五个模块：

**1. 业务流程重塑**

传统业务流围绕人工操作设计，步骤冗长且依赖多层审批。接入 Agent 要求将流程解构为状态机。

企业需要按自主执行特性重塑流程：明确哪些节点由算法自主流转，哪些动作保留人工终审，哪些异常纳入预设规则。流程不重做，Agent 只是给旧流程多套了一层，多层串行审批还会让它卡在等待节点上。

**2. 运行时护栏**

纸面安全制度之外，系统里要有代码级的运行时护栏。护栏放在模型给出动作意图和底层系统真正写入之间，先检查，再放行。

运行时护栏包含三项机制：第一是工具调用的白名单与参数模式强校验，拦截未声明的系统调用；第二是高危写操作的权限沙箱，限制单次任务的最大操作金额、修改记录条数与请求频次；第三是敏感数据防泄漏过滤器，对输入和输出进行双向合规扫描。

**3. 命名负责人与接手路径**

研发不再盯盘以后，要有明确的人或部门为自动执行负责。

扩产前需在组织层面落实三类责任人：业务负责人确认业务规则，技术负责人监控可用性与延迟，合规负责人评估数据与操作风险。同时，系统需内建人工接手路径。当 Agent 连续调用失败、置信度低于阈值或侦测到意图冲突时，系统立即停止自动执行，把上下文完整移交给对应业务人员。

**4. 操作回滚与全链路追踪**

出了错能撤回、能追查，Agent 才适合接写操作。

针对写操作，工程团队必须提供原子化回滚能力。若 Agent 在执行批量修改或提交订单过程中断，系统应自动恢复至初始事务状态。同时，提示词输入、推理链路、外部 API 参数与返回值，以结构化形式写入防篡改日志，支持事后现场还原与合规审计。

**5. 综合结果度量体系**

衡量 Agent 在生产里跑得怎么样，要有覆盖全流程的指标。

生产环境度量看板应追踪四项核心指标：端到端业务闭环率、人工介入修正频率、单任务算力与接口成本，以及异常补偿重试次数。只有当人工介入率持续走低且单位成本可控时，业务线才具备扩大流量的合理性。

## Agent 试点扩生产：常见问题

### 为什么大模型评测跑分优秀的 Agent，在生产环境中经常报错？
公开评测主要衡量模型在封闭边界下的单轮或少轮逻辑推演，输入大多经过格式规范。真实生产环境则充斥着非标准的脏数据、网络抖动、超时以及上游系统的非预期返回。大模型缺乏对异常环境的原生防御能力，一旦外部变量超出提示词上下文的预设范围，模型很容易产生错误调用或重复重试。

### 企业推进扩产时，应该先改写业务流程还是先搭建技术护栏？
两项并行推进，但先后有别。技术护栏管安全，防止逻辑缺陷引发数据篡改或财务损失；流程重塑管效率，决定自动化能走多远。实践中先定写权限的拦截规则，让系统有兜底，再按业务特点逐步调整任务节点。

### 生产环境中的运行时护栏具体由哪些模块组成？
生产环境的运行时护栏一般分三层：输入侧做敏感数据过滤和注入探测；决策侧用策略即代码（Policy-as-Code）校验工具调用是否在白名单内、参数是否合规；执行侧对高危写操作设上限，限制单次金额、修改条数和请求频次，超限就拦截或转人工。三层都独立于模型运行，按外部规则直接拦下越权动作。

先把这五项逐一勾完，把人工接手通道接好，再逐步放开业务流量。
