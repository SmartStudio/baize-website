差旅预订 Agent 替员工订酒店时，先按员工本人的分子公司、部门、职级和目的地城市查出对应的差旅标准，默认只在标准范围内筛选房型。遇到房源超标，差旅预订 Agent 不自己放行，按企业配置的事中管控规则直接拦下或转入超标审批流程；超标原因由员工本人填写，直属主管或指定审批人通过前不下单，个人自付部分也要员工本人确认。

## 订酒店前先对哪条差旅标准

企业通常把差旅标准嵌进商旅预订流程里，员工发起订房请求时匹配对应的额度。差旅预订 Agent 接手查房和比价动作后，第一步是读取当前入住人的组织与身份信息，把分子公司、所属部门、职级、目的地城市级别以及出行类型逐一对齐，算出这一单适用的每间夜价格上限和最大间夜数。

日常出差常遇到多人同行或特殊时期房源紧张，企业的差旅标准可以配置成包含合住差标叠加、同行人差标就高、展会或旺季特殊场景临时上浮等细则。当同一笔订单同时命中多条规则时，系统按预先排定的规则优先级生效。差旅预订 Agent 在调取房源列表时，按生效的额度过滤候选酒店，把符合差旅标准的房型排在前面供员工挑选。

## 超标订单是直接拦还是走审批

员工如果点名要住超出每间夜价格上限的酒店，或者预订天数超过了单次出差允许的最大间夜数，差旅预订 Agent 不能替员工直接生成正式订单。商旅平台和企业事中管控接口可以配置成两种处理方式：一种是超标直接拦截，页面提示超出差旅标准并退回重选；另一种是允许继续提交预订请求，但要求填写超标原因并触发超标审批。工具调用到哪一步可以直接放行、哪一步要拦下等审批，设计思路见 <NoteLink slug="agent-tool-call-auto-approval-rules">Agent 工具调用自动审批：哪些放行、哪些拦下</NoteLink>。

部分企业把超标管控拆成企业支付与个人自付两部分结算：差旅标准以内的房费由企业账户统一支付，超出差旅标准的差额部分可以配置成由员工个人自付。采用混合支付规则时，差旅预订 Agent 算清企业承担金额与个人自付差额，并在下单前停下来等待确认，不能绕过管控规则直接用企业账户付全款。

## 谁来审批与员工本人要确认什么

订单触发超标审批后，可以配置成推送到企业自己的审批系统，由员工的直属主管或企业指定的审批人审核，审批结果再回传到预订端。审批人在工作台里查看入住城市、酒店名称、超标金额及超标原因，给出通过或驳回的结果；审批结果回传之前，差旅预订 Agent 保持待命，不向酒店或商旅平台下达锁房付钱指令。

在这个过程里，有两件事要由员工本人亲自操作。第一，超标原因由员工自己如实填写，比如客户指定入住同一家会议酒店或周边同档次协议酒店已满房，差旅预订 Agent 不替员工编造或代写超标理由。第二，如果涉及超标差额个人自付，要由员工本人在支付确认页点选同意并完成个人支付授权，Agent 不能替员工勾选个人自付协议。

## 规则谁维护与事后怎么查

差旅标准及配套的优先级、临时上浮规则，统一由企业行政差旅管理员和财务部门在后台维护。差旅预订 Agent 对差旅标准库只有只读查询权限，没有修改权限；哪怕员工或主管在对话里要求临时调高额度，Agent 也不会去改后台配置。差旅支出花的是企业差旅业务费用，Agent 本身调用模型产生的费用另外算，这部分预算怎么管见 <NoteLink slug="ai-usage-pricing-budget">AI 按量计费后，企业一年一编的预算还管得住吗？</NoteLink>。

酒店预订成功后，如果员工后续发起行程变更、延住或退订，同样受差旅标准和退改签规则约束；变更后若导致间夜单价或总间夜数超标，照样重新触发拦截或审批。从最初查询差标、提交预订、填写超标原因、主管审批回传，到最终企业支付、个人自付拆分结算与退改操作，全程在线上留存记录，每次差标改版也保留历史版本记录，供财务与内审部门随时抽查追溯。

## 差旅预订 Agent：常见问题

### 两个人出差合住一间房，或者跟高职级同事同行，标准怎么算？

按企业在系统里配置的合住差标叠加或同行人差标就高规则计算。行政和财务事先在差旅标准库里设定好多人合住的额度叠加方式、同行出差是否允许按高职级人员标准就高，以及多条规则冲突时的生效优先级，差旅预订 Agent 读取同行人名单后按生效规则匹配对应上限。

### 订好酒店以后临时改期或退房，还会经过规则校验吗？

会。变更和退订同样受差旅规则约束。员工通过差旅预订 Agent 申请改期、延住或退订时，系统重新校验变更后的每间夜价格、累计间夜数；一旦改期后的房价突破差旅标准，同样按规定执行拦截或重新发起超标审批，并留存变更记录。

### 差旅标准变了，Agent 什么时候按新标准订？

行政和财务在后台发布新版差旅标准并到达生效时间后，差旅预订 Agent 发起的新预订查询即按新标准匹配额度。差旅标准每次改版可以配置成保留版本记录和生效时间，改版前已经审批下单的订单，审计时对照下单当时生效的那一版差旅标准来查。
