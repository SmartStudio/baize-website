月末结账时，月结关账 Agent 只起草调整分录，不直接写总账；起草的内容统一放在复核工作区当建议看，正式凭证照走标准审批流程入账，由人录入或有权审批人批过之后才过账，准备分录的人不能自己批自己的单子。会计核调整分录盯三样：计算依据能不能追到原始数据和总账、金额按依据重算对不对、借贷科目和期间对不对；落在企业定的容差带内的走快速审批加抽样复核，超出容差或越过重要性阈值的逐笔全量复核。

## Agent 在月结里起草哪些分录

月结里适合交给 AI 做的有五件事：往来与明细对账勾对并按原因归类差异、给出费用计提和摊销建议、做科目余额滚动计算、写期间波动分析说明初稿、核对结账检查清单。其中应付账款对账往后延伸的关卡参照 <NoteLink slug="ap-invoice-agent-payment-control">应付账款 Agent 从对账做到付款，中间哪几道关不能省</NoteLink>。

碰外部传来的单据时，第一步是掐掉写账权限。外部发票和供应商对账单属于不可信的外部文件，读取这些文件的环节不给写入工具，只把金额和单据要素提出来做核对，防住外部文件里夹带的异常内容改动账套。

生成的调整分录草稿都留在复核工作区，标明是建议。正式凭证经企业原有的审批流程入账，由总账会计录入或经审批人点同意后过账，守住双人复核。

## 每条调整分录要带什么依据

草稿上要是只给一个科目和一个数，审批人没法复核。每条调整分录都要挂上结构化的计算依据，把算法和数源一块摆给审批人看：

- **历史均值与未结订单**：预提常规费用时，附上近几个月实际发生额的滚动均值，或者挂上未结采购订单明细。
- **合同计划与季节规律**：附上合同付款计划、摊销期间和科目的季节性规律；属于月末预提性质的计提类分录，可以配置成标上下期期初自动冲回。
- **支撑文件与总账查询**：写清对应的支撑文件编号或总账查询入口，总账会计和财务经理点开就能核对底层明细。

做科目余额滚动计算时，算出来的结果要能跟总账期末余额勾稽上；碰上对不平的款项，草稿里如实把差额列出来，不硬凑平账。要是查不清差异原因，草稿上直接写原因不明、交财务经理看，不编造理由。

## 会计按什么顺序核与分级怎么分

总账会计拿到草稿后按固定顺序往下核：先点开支撑文件或总账查询，看列出的依据能不能追回原始数据和总账；再照着草稿写的算法重算一遍，看金额算得对不对；最后看借贷科目、会计期间和下期期初自动冲回标记有没有挂错。

关账高峰期单子集中，为避免审批人对着几百条建议一路点同意，可以配置成按容差带分级复核。落在企业定的容差带内的常规建议，走快速审批配抽样复核；超出容差或超过重要性阈值的，全部拉出来做全量复核并强制写明理由。正式进月结前，财务团队可以先挑已关账的历史月份让 Agent 重跑几遍，拿生成的草稿跟当时实际入账的分录逐笔对账，评测怎么跑见 <NoteLink slug="agent-eval-suite-pass-rate-variance">Agent 评测怎么做：每个任务跑几次才算数</NoteLink>。

## 留痕与审计要看什么

审计查关账底稿，主要问三件事：机器算了什么、谁复核的、事后能不能重算出一样的数。月结关账 Agent 的记录按四层留底：

- **输入数据快照**：记清起草分录时用了哪份总账数据、卡在哪个截止时点的数据快照；要是直接读随时在变的实时数据，回头审计复现不出当时的数。
- **机器初稿归档**：每份 AI 初稿都带上时间戳和系统版本存底，在人工正式批准前标明是机器生成。
- **人工复核归属**：记下具名审批人、审批时间，还有批之前会计动没动过初稿，原样接受和改后接受都要分开记清楚。
- **当期模型与约束**：记下当月关账用的哪个模型版本、配了什么指令约束，以及关账中途有没有人未经批准改过配置。

## 月结关账 Agent：常见问题

### 科目余额滚动发现跟总账期末余额对不平，Agent 会自动补差额吗？

不会，也不该这么配置。科目余额滚动计算要能跟总账期末余额勾稽上，一旦对不平，草稿直接把差异金额和涉及的明细亮出来，不硬凑平账分录。按现有账务规则要是查不出差在哪，草稿上直接标明原因不明、交财务经理排查，不自己编解释。

### 供应商发来的对账单和发票，能直接让 Agent 读完改账吗？

不能。外部传来的发票和供应商对账单都算不可信的外部文件，读取和解析环节只提票面金额和单据要素，不给写入工具权限。比对出来的差异如果确实要调账，也只能在复核工作区起草调整分录建议，等总账会计核完原始单据，再走双人复核的审批流过账。

### 调整分录被会计改过，Agent 下个月还会按原来的算吗？

要是只手动改了当期凭证草稿、没动底层规则，到了下个月它照旧按老算法算。规范做法是：总账会计改完调整分录草稿，顺手把改动原因记下来；要是计提或分摊的算法规则本身要调，由财务人员改规则库，报财务经理批过之后正式生效。Agent 不会自己在后台跟着改，下个月统一按批过的新规则重算。
