月结关账 Agent 在月末只起草调整分录，不直接写总账；输出统一放在复核工作区作为建议，凭证走标准审批流程入账，由人录入或人批准后过账，准备分录的人不能自己批准。会计核对调整分录时核三样：依据能不能追到原始数据和总账、金额按依据重算对不对、借贷科目和期间对不对；落在企业定的容差带内的走快速审批加抽样复核，超出容差或超过重要性阈值的逐条全量复核。

## Agent 在月结里起草哪些分录

AI 在月结里适合做五件事：往来与明细对账勾对并按原因归类差异、生成各类费用计提和摊销建议、做科目余额滚动计算、写期间波动分析说明初稿、核对结账检查清单。其中应付账款从对账到付款的关卡设计，见 <NoteLink slug="ap-invoice-agent-payment-control">应付账款 Agent 从对账做到付款，中间哪几道关不能省</NoteLink>。

处理外部单据时要先锁死写入权限。发票、供应商对账单是外部文件，不可信；读取这些文件的环节不要给写入工具，只提取金额和单据要素做比对，防止外部文件里夹带的异常内容改动账套。

生成的调整分录草稿都留在复核工作区，标为建议。凭证经企业原有的审批流程入账，由总账会计录入或有权审批人批准后过账。

## 每条调整分录要带什么依据

如果草稿只给一个科目和金额，审批人没法复核。每条调整分录都要附结构化的计算依据，让审批人同时看到算法和来源，不只是一个数：

- **均值与订单依据**：预提常规费用时，附上近几个月实际发生额的滚动均值，或挂接未结采购订单明细。
- **合同与季节性依据**：附上合同付款计划、摊销期间和科目季节性规律；属于月末预提性质的计提类分录，可以标注下期期初自动冲回。
- **文件与查询来源**：注明对应的支撑文件编号或总账查询路径，方便总账会计和财务经理直接点开核对底层明细。

做科目余额滚动计算时，结果要能勾稽到总账期末余额；遇到对不平的款项如实揭示差异金额，不硬凑平账。遇到差异原因不明确时，草稿上直接写原因不明、交财务经理处理，不编造理由。

## 会计按什么顺序核与分级怎么分

总账会计按固定顺序核对草稿：第一步点开支撑文件或总账查询，核对计算依据能不能追到原始数据和总账；第二步按草稿列出的算法依据重算一遍金额对不对；第三步核对借贷科目、会计期间和下期期初自动冲回标记对不对。

为避免审批人在关账高峰期对着几百条建议一路点同意，企业可以配置按容差带分级复核。落在企业定的容差带内的常规建议，走快速审批加抽样复核；超出容差或超过重要性阈值的，走全量复核并强制写复核理由。正式上线前，团队可以先拿已关账的历史月份让 Agent 重跑一遍，拿生成的草稿和当时的实际分录逐笔比对，评测跑法见 <NoteLink slug="agent-eval-suite-pass-rate-variance">Agent 评测怎么做：每个任务跑几次才算数</NoteLink>。

## 留痕与审计要看什么

审计会问三件事：AI 参与编制的数据做了什么、谁复核了、能不能复现。所以月结关账 Agent 的记录按四层留：

- **输入溯源**：记下起草分录时用了哪份总账数据、哪个截止时点的数据快照；如果直接读实时会变的数据，事后审计就无法复现当时的计算结果。
- **输出留痕**：每份 AI 初稿都带时间戳和系统版本保存归档，在人工正式批准前标明是机器生成。
- **人工归属**：记下具名审批人、审批时间，以及审批前会计有没有改过初稿，原样接受和改后接受都要记清。
- **模型治理**：记下当月关账用的哪个模型版本、什么指令约束，以及关账中途有没有未经批准的改动。

## 月结关账 Agent：常见问题

### 科目余额滚动发现跟总账期末余额对不平，Agent 会自动补差额吗？

不会，也不该这么配置。科目余额滚动计算要能严格勾稽到总账期末余额，遇到对不平的款项直接如实揭示差异金额和涉及的明细，不硬凑平账分录。如果按现有账务规则查不出差异原因，工作台草稿上直接标注原因不明、交财务经理排查处理，不自行编造解释。

### 供应商发来的对账单和发票，能直接让 Agent 读完改账吗？

不能。外部传来的发票和供应商对账单属于不可信的外部文件，读取和解析这些文件的环节只提取票面金额和单据要素，不给写入工具权限。提取出的差异如果需要做账务调整，同样只能在复核工作区起草调整分录建议，由总账会计核对原始单据后，走双人复核的审批流程过账。

### 调整分录被会计改过，Agent 下个月还会按原来的算吗？

如果只手动改了当期凭证草稿而没改底层规则，下个月它还会按原来的算法算。规范做法是：总账会计改了调整分录草稿后，把具体的改动原因记录下来；如果需要长期调整计提或分摊算法规则，由财务人员修改规则并经财务经理审批后正式生效，Agent 不会自己在后台学着改，到了下个月统一按批准后的规则重算。
