采购跟单 Agent 在订单下达后负责发现未确认或逾期订单、发催单邮件、把供应商回信整理好并与系统字段比对；一旦确认发生交期延误，先告诉用这批料的物料计划员和生产计划，会影响对客户交期的，再由计划或销售按已有的交期承诺流程通知客户。供应商回信里的新日期由采购员确认后才写回系统，Agent 不直接改对客户的承诺。

## 每天筛哪两类订单与任务怎么配

采购订单下发给供应商后，跟单从盯确认和盯到货开始。根据一款主流 ERP 的采购智能体文档（该功能是面向生产环境的预览版），默认有两个跟单任务：一个找供应商还没确认的采购订单（确认收货日期为空、还有未交数量），另一个找已经发生交期延误的订单（确认收货日期早于今天、还有未交数量）。

这两类任务的条件可以改，每个用户的任务各自配置。企业落地时，可以让每位采购员按自己负责的供应商或物料品类配置任务条件，各自盯住名下哪些订单还没拿到供应商确认、哪些订单已经过了确认收货日期还没交齐。日常跟单只针对已经走完审批并下达的采购单，不涉及前期供应商准入筛选和下单审批环节。

## 催单邮件怎么发与不回怎么再催

按这款主流 ERP 的采购智能体文档，对找到的每张订单，智能体生成一封发给供应商的跟进邮件草稿；可以配置邮件里带哪些字段、签名、语气（正式或随意、紧急或不紧急）。可以把邮件存为草稿由人审过再发，也可以配置成自动发送；配置成自动发送时，邮件页脚（例如注明邮件由 AI 协助撰写）是必填的。关于 Agent 发信要不要先经人工审批，见 <NoteLink slug="agent-read-mail-vs-calendar-send">AI Agent 权限：读邮件行，发信要先批吗</NoteLink>。

同一张订单默认只生成一封跟进邮件，除非订单有变化。如果供应商不回、要再催一次，文档的办法是建两个条件相同、日期范围不重叠的任务；要注意日期范围重叠会让同一张订单被两个任务同时评估。企业把催几次、不同阶段语气多重、什么时候升级到采购主管，提前写进跟单规则里照着配。

## 供应商回信怎么比对与谁来确认

催单邮件发出后，智能体还可以读供应商来信，判断是订单确认、变更请求、拒绝还是其他，并把信里的信息和系统字段比对、显示差异，由采购员核对后再更新系统字段。结合文档说明，不同回信情形按下面这几条处理：

- **常规交期确认与顺延**：供应商回信给出确认日期或新交期时，智能体显示与系统字段的差异，由采购员核对确认后写回系统。
- **单价涨降的商业变更**：来信涉及单价涨降的，会被标成需要采购员决定或批准的商业变更，不直接改采购价格。
- **剩余数量不交的例外**：供应商说剩余数量不交了，会被标成通常需要采购员介入的例外，由采购员另找货源或重新谈。
- **目前不支持的情形**：文档列出目前不支持供应商提出把一行拆成多次交货、改某行的收货地点、换成另一个经营实体发货，遇到这类回信直接转采购员人工改单。

## 延误确认后先通知谁与怎么联动

当采购员核实供应商回信、确认某批物料发生交期延误时，先告诉用这批料的人：物料计划员看库存缺口和替代料，生产计划看要不要调整排程。只有内部先把缺口和排程算清楚，才能知道这批原料晚到会不会波及成品出货。

如果评估下来会影响对客户的交期，再由计划或销售按已有的交期承诺流程通知客户。对客户交期承诺怎么管、晚了谁来担责，见 <NoteLink slug="delivery-promise-agent-late-order">交期承诺 Agent 报了交期，晚了谁来背？</NoteLink>。整个过程中，采购跟单 Agent 只管催单、理清回信和提醒内部下游岗位，不直接改对客户的承诺。

## 采购跟单 Agent：常见问题

### 催单邮件能让 Agent 自动发吗？

可以配置成自动发送，但按一款主流 ERP 的采购智能体文档，配置成自动发送时，注明邮件由 AI 协助撰写的邮件页脚是必填的。团队刚开始用时，先设成存为草稿由采购员审过再发更稳妥，等核准筛选条件和收件人无误后再按需开启自动发送。

### 供应商要拆批交货怎么办？

转采购员人工处理。按上述采购智能体文档，供应商提出把一行拆成多次交货、改某行的收货地点、或者换成另一个经营实体发货，都属于目前不支持的情形，由采购员人工处理。

### 交期延误了，Agent 能直接改系统里的交货日期吗？

不直接改。出现交期延误时，按文档的做法，采购跟单 Agent 把供应商来信信息和系统字段比对后显示差异，由采购员核对再更新系统字段；涉及对客户的交期，由计划或销售走原有流程处理。
