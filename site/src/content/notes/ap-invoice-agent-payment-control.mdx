应付账款 Agent 把对账、处理差异、分摊科目一路做到付款时，有几道关不能省：发票与采购订单、合同及入库收货单的匹配差异要有处理记录；供应商银行账户或收款信息的变更要走独立核验（通过预留电话回拨确认），Agent 不能自行修改；重复发票检查；超出审批额度、政策或品类规则的交易转人复核；付款批次放款前复核，付款后对账，每一步留审计记录。

Freehand 10 月 13 日发布 Freehand Pay。按它的新闻稿，以前付款审批是自动化流程的终点，后面的放款交给财务；现在 Agent 会把已批准的发票接着推进到付款和对账。Agent 在客户财务部门定的审批额度、政策和品类规则里运行，超出范围的交易转人复核，每个决定都记审计记录。支付通道由 Stripe 支持。

## 以前流程停在哪，现在往后多走了哪几步

以前的财务自动化通常停在发票识别和三单初核。系统做完 OCR、核对采购单没问题之后，生成一张待审表格，后面的网银制单、复核和打款全由财务手工做。

现在的应付账款 Agent 往前多走了几步。它提发票、对合同和收货单、填会计分录，然后调支付接口打款，付完款再核对银行对账单。

在把流程接上银行出金之前，团队要给整条链路加上防御规则，相关的治理思路见 <NoteLink slug="agent-governance-before-scale">Agent 治理要赶在扩规模之前：推荐错了能不采纳，执行错了已经发生</NoteLink>。

付款之前的供应商筛选环节，短名单理由怎么写，见 <NoteLink slug="procurement-agent-supplier-shortlist">采购 Agent 挑供应商，短名单理由要写多细？</NoteLink>。

## 匹配差异处理：Agent 可以查证，结论要留存依据

发票金额跟采购订单、入库单有点微小出入很常见，比如运费分摊、单位换算取整或者合理损耗。

应付账款 Agent 能做很多查证的事。它可以查合同里的溢短装比例，在群里催采购补交收货单，也能发邮件跟供应商核对单价。不过，Agent 怎么处理这些差异，过程要透明。

每笔调整都要记清凭据：差额依据哪份补充说明、谁确认了折让、记入哪个会计科目。要是差异超出约定的容差，Agent 只能整理好证据标出疑点，交给会计来审，不能自己把账抹平。

## 收款账户变更：Agent 不能改收款账户

财务上常见的骗局之一，是假冒供应商改银行账户。骗子黑进供应商邮箱，发来正式发票，顺便在备注里写一句“账户变了，请打到新卡”。

要是让 Agent 看到文字就去改供应商主数据的银行账户，公司的钱很容易直接打给骗子。

这里的规矩只有一条：Agent 不能改收款账户。一旦发现发票上的开户行或账号跟系统记录对不上，Agent 要直接停下这笔付款，通知财务。要改账户，得走另一条路核实：财务打合同里预留的座机电话找到对方确认，拿到盖公章的开户证明，经财务总监批准后，再由人工在系统里改。

## 重复发票与拆单规避的侦测

第一类是换个样子的重复发票。比如先拿电子发票打印件报销，过一个月又拿扫描件生成 PDF 重复交；或者在发票号前后加空格、符号来躲查重。Agent 要综合比对发票号、开票日期、金额和合同号，交叉查重。

第二类是刻意拆单。为了绕开某一级审批，把一笔采购拆成几张金额刚好低于审批线的发票。Agent 审查时会扫描同一供应商在相近时间里的开票频次，发现拆单痕迹就合并送审。

## 额度、政策与品类规则：超限转人复核

审批额度：哪些金额可以匹配无误后直接付、哪些要进人工复核，门槛由财务负责人按审批权限定。

特殊费用政策：差旅餐饮、礼品、公关、咨询这些敏感品类，就算单据齐全，也要交由人工把关真实性。

跨期和预算：发票如果跨了财年，或者项目预算不够付这笔款，Agent 要停下来转给人工处理。

在给 Agent 更多自主权之前，各项异常的人工接管路径怎么定，可以对照 <NoteLink slug="agent-pilot-to-production-checklist">Agent 试点能跑通，扩到生产还缺哪几项？</NoteLink>。

投标一侧由 Agent 起草标书时，废标条款谁来兜底，见 <NoteLink slug="bid-agent-tender-response">投标 Agent 写标书，废标条款谁来兜底？</NoteLink>。

## 批次复核、职责分离与付款后对账

单张发票审查完后，Agent 会汇总出一份批次清单。把付款指令推给银行或支付通道之前，由出纳或资金主管核对总金额和笔数，确认放款。

职责也要分开：定业务规则的人、管供应商银行主数据的人、最终批付款的人，不能是同一个人。Agent 拿到的凭证也一样，它只能对单据和起草记录，不能同时拥有修改主数据和最终打款的权限。

款项付出去后，流程还没完。Agent 会拉取银行回单或支付通道返回的流水，跟应付凭证逐笔对账。要是发现退汇或者账目没对齐，马上报警查原因。

刚开始用应付账款 Agent，建议先从水电费、宽带费、固定月租这类账单标准、金额固定的供应商试起，把核验逻辑跑顺了，再扩到复杂的采购业务。

## 应付账款 Agent：常见问题

### 引入 Agent 后，财务出纳的日常工作会发生哪些变化？

出纳的精力会从手工录单、网银制单这类重复活转出来，主要负责处理异常和盯资金。出纳不用再逐笔复制粘贴账号金额，而是看 Agent 筛出来的疑点清单、打电话做线下回拨核实，并在最后确认整批付款指令。

### 供应商发票上的开票金额与采购订单存在轻微误差时，系统如何处理？

系统通常按预设的容差规则分流。单价或税额如果出现微调，且在容差幅度内，记录差异原因后可以调整科目放行；容差幅度由财务和采购在合同里约定。如果超出容差，就打上标记转交采购和供应商核对，系统不自动抹平。

### 企业如何建立多层防线的付款控制机制？

企业建立付款控制机制要贯穿事前、事中与事后三层防护。事前在供应商主数据库中建立变更隔离与人工双向核验通道；事中由应付账款 Agent 严格执行三单匹配、重复票据拦截与额度超限转审，并由出纳人员进行批次授权；事后引入自动银行回单核销与异常流水回溯，确保全链路具备审计证据。
