入职开通 Agent 按岗位权限模板开账号，模板由各部门负责人和 IT、信息安全一起定。HR 系统里的岗位和部门是触发依据，信息对不上就停下问 HR；模板外的权限走申请单由人批；财务付款、客户数据导出、系统管理员这类敏感权限不放进 Agent 自动开的范围；开完把清单发给员工和直属主管确认，转岗时按新岗位收回旧权限。

## 岗位权限模板谁定与怎么写

业务部门负责人把本部门每个常见岗位拉出来，和 IT、信息安全坐在一起逐个梳理：这个岗位进公司第一天要登哪些系统、在每个系统里给什么角色。梳理完制成标准模板表，每一项账号权限后面都写清楚对应的日常工作内容，不塞用不上的闲置角色。

比如同样是销售部门，负责线索跟进的岗位只给客户管理系统的录入与查看角色，不给批量导出和合同审批角色。模板定好后入库归档，后续哪个部门因为业务调整想往模板里加一项新系统或新角色，先提变更单由部门主管、IT 和信息安全共同批准，每次修改都在系统里留存版本记录。

## Agent 照着入职单怎么开账号

HR 在 HR 系统里录完入职单，Agent 读到新员工的部门、岗位名称、入职日期和直属主管，去模板库里匹配对应的岗位模板。匹配上之后，Agent 依次去邮箱、办公软件和模板列出的业务系统里建账号、绑角色，并把每一步操作的时间、系统名和分配结果记进日志。

如果入职单里岗位或部门信息缺失、对不上，或者填的岗位名称在模板库里找不到对应项，Agent 马上停下来发消息问 HR，不自己猜一个相近的岗位往下跑。Agent 自己调用接口时用单独的服务账号，手里的权限只够在指定系统里建普通账号和绑基础角色；Agent 自己的权限怎么分级开，见 <NoteLink slug="agent-tool-permission-ladder">Agent 权限管理怎么分级：工具权限先开哪类</NoteLink>。

## 模板外与敏感权限怎么走审批

新员工入职后因为接手专项工作，需要用到岗位模板之外的系统或更高角色，由员工本人或直属主管在流程系统里提申请单。申请单上写明具体用途、涉及的系统模块和使用期限，流转给对应业务系统的负责人和信息安全审批，批过之后再开通。

财务付款审批、客户全量数据导出、生产数据库读写、系统管理员这类高风险账号权限，从一开始就不写进任何岗位的自动开通模板。比如新招进来的是财务主管或运维工程师，Agent 按岗位模板开通普通账号和角色；涉及资金、大批量敏感数据和后台管理的敏感权限由人审批、手动开通，由专人核实身份和岗位任命文件后配置。

## 开完怎么核对与转岗怎么收旧换新

Agent 把模板里的账号全部建完后，自动生成一张开通清单，同时发给新员工和他的直属主管。员工和直属主管分别对照手头的工作安排核对清单，看有没有多开不该进的系统、或者漏了干活要用的基础角色，发现不对就反馈给 IT 处理；信息安全团队也会定期抽查在职人员的权限表和岗位模板是不是对得上。

员工在公司内部调动部门或换岗位时，HR 系统里一改岗位信息，工作流先照着原岗位模板把他在旧部门用的业务系统角色收回来，再按新岗位模板补上新角色，不让新旧几个岗位的权限一路叠着攒下去。员工自己搭的 Agent 在转岗、离职后归谁，另见 <NoteLink slug="agent-owner-when-employee-leaves">员工离职或转岗后，他搭的 Agent 归谁接手</NoteLink>。

## 入职开通 Agent：常见问题

### 新员工第一天还没定具体岗位，Agent 先开哪些？

还没定岗的新员工，Agent 只开全员通用的基础项，比如企业邮箱、日常考勤和即时沟通软件。涉及具体业务的 ERP、客户管理或研发代码库先不开，等部门把具体岗位落进 HR 系统后，再按岗位模板补齐。

### 主管在聊天群里口头说给新员工加个权限，Agent 能直接加吗？

不能，口头消息和群聊记录不能作为开通依据。模板外的权限统一在系统里提申请单，写清用途和期限，由主管和对应系统负责人批完留痕后才能配置。

### 试用期员工的账号权限，要不要先收紧？

按单位规定和岗位模板来定。日常干活离不开的基础录入与查询角色，入职当天就按岗位模板给齐；涉及大额审批、核心资料库访问或对外发布等敏感的账号权限，可按单位规定在转正后申请，试用期内确需使用就走单独审批单，由直属主管和系统负责人审批后人工开通。
