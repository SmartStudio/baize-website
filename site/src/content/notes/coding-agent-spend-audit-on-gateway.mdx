团队都在用 Codex、Claude Code，月底财务问「这个月 AI 花了多少」，工程对不上、财务对不上、个人报销单也对不上。问题通常不在模型贵，而在账记在个人 key 上。

这页不重复「别再买账号」。只讲三件事：谁对账、日志要留哪些字段、个人 key 为什么进不了公司账。

## 谁对账

对账的人不能是「谁用谁报」。财务要的是一张组织账单：哪个项目、哪条业务线、哪个角色。工程要的是一次调用能追到任务和仓库。这两边必须对同一个入口。

建议固定三个角色：财务看总额和项目分摊；工程负责人看超限和异常调用；平台/网关管理员改限额、发密钥、留日志。谁改 spend cap，必须留操作者，不能只有模型供应商后台的一个邮箱。

## 日志要留哪些字段

没有字段，就没有企业账。一次调用至少留下这些，才能对得上：

- 谁：组织成员或角色 ID，不是个人 Chat 昵称
- 哪个项目 / 哪个仓库 / 哪次任务
- 哪个模型、多少 token、多少钱
- 何时、从哪条路由出去、有没有降级
- 这次调用是否带出敏感路径（能记标记，不必把原文都留下）

这些日志要落在你们自己的 collector / 网关，不要只存在模型厂商的控制台。厂商控制台人员一变、团队一拆，账就断。

## 个人 key 为什么进不了公司账

个人 key 的付款主体是个人卡或个人套餐。发票抬头、汇率、赠金、家庭计划，财务都入不了账。一个人离职，key 停了，历史用量也带不走。同一个任务两个人各打各的 key，成本按项目加总一定错。

所以对账只能发生在组织签发的凭证上：网关发的 token，或企业席位。个人 key 可以试用，不能作为月底对账依据。验收很简单：抽一个月，按项目加总，能对上财务实付，且点开一笔能看到人和任务。对不上就还是个人账。
