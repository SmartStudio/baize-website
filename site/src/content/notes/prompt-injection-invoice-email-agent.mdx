提示词注入已经开始针对企业里读邮件的 Agent，防住它靠三层控制：邮件进来时先扫隐藏内容，给 Agent 只读不发的最小权限，付款继续走应付账款原有的审批和回拨核实。读邮件的 Agent 看得见人眼看不见的字符，权限放得过宽，外部邮件夹带的文字就可能被当成命令。转发到新地址、录入应付、修改供应商收款信息，都留给人确认。

## 这批发票邮件藏了什么

十月下旬，一家邮件安全公司发了一份公开报告，披露了一批针对读邮件 AI 的发票诈骗邮件。发信人冒充收件企业自己的高管，附上发票 PDF，底下伪造了几层往来回复，催收件方赶在折扣到期前付款。光看表面，这是常见的冒充高管催款骗局。

这批邮件在正文底层还藏了一段写给读邮件 AI 看的隐藏指令。一层用样式把文字设成极小号、白色、零宽高，人眼和读屏软件都看不到；另一层用不显示的 Unicode 标签字符编码。解码后的指令是让 Agent 把这封邮件连同发票 PDF 原样转发到一个看起来像应付账款部门的地址。报告没有说有 Agent 真的照做，也没有说有钱付出去，但这类同时算计人和读信工具的邮件已经进了收件箱。

## 隐藏指令怎么骗过 Agent

这类攻击叫间接提示注入，属于提示词注入在外部内容场景里的常见形态。攻击者不用进企业后台，只要把指令藏在 Agent 处理的外部内容里就行，常见载体有邮件、网页、文档和日历邀请。人看的是排版后的画面，Agent 拿到的是底层源码与全部字符，零宽高文字和不显示的编码字符都会送进模型。

模型上下文要是没分清系统指令与外部来信，就会把邮件夹带的隐藏指令当成命令执行。别的流程模块摘录外部邮件后再传过来的文本，同样可能带着未清理的指令；跨 Agent 转来的内容能不能直接执行，见 <NoteLink slug="agent-to-agent-trust-boundary">多 Agent 安全：转来的指令能直接照做吗</NoteLink>。防守时要把外部内容当数据、不当指令，和系统指令分开并标明来源；同时在邮件进来时检测隐藏文本和不显示的字符，可以配置成检测到隐藏指令的邮件打标签、隔离并通知 IT 安全，不交给 Agent 处理。

## 读邮件的 Agent 给多大权限

Agent 被注入后能做什么，取决于它有什么权限。这批诈骗邮件指挥 Agent 把原信和 PDF 转发出去，赌的就是读邮件的 Agent 同时拿着发信接口。要是这个 Agent 只读不发，隐藏指令就算骗过了模型，到了工具调用那一步也会因没有权限而停住。

IT 安全负责人与 Agent 管理员按完成任务所需的最小权限收口，可以把下面几条规则写进权限配置。

- **邮件通道只读不发**：整理信件的 Agent 只开放读取邮件、解析发票 PDF 和生成内部待办草稿的权限，不给外发或对外转发接口。
- **高风险动作留给人确认**：转发到新地址、录入应付系统、修改供应商收款信息这类高风险动作，默认要人明确确认，Agent 不能自行提交。
- **可疑来信提前移出队列**：入口检测标出含有隐藏样式或不显示字符的邮件后，直接隔离转交 IT 安全核查，不进 Agent 读取队列。

## 付款前哪几道关不交给 Agent

就算伪造高管回复、催促折扣到期前打款的邮件混进了待办清单，钱能不能付出去，靠的还是应付账款原有的审批和回拨核实。攻击者伪造往来记录并用折扣期施压，就是想让经办人跳过常规核对。企业上了读邮件的 Agent，原有的付款内控一步也不能省。

财务应付拿到 Agent 整理的账单草稿后，照常核对采购合同、验收记录与发票明细，检查收款账户与供应商档案是否一致。遇到高管名义临时催付、催赶折扣期打款或更改收款信息的情况，经办人按制度用内部已知号码独立回拨核实，不轻信邮件里的回复链。付款前各环节怎么管住风险，见 <NoteLink slug="ap-invoice-agent-payment-control">应付账款 Agent 从对账做到付款，中间哪几道关不能省</NoteLink>。

## 提示词注入：常见问题

### 报告里的这批发票邮件，真有企业的 Agent 中招付款了吗？

公开报告没有说有企业的 Agent 真的照着邮件里的指令执行转发，也没有提到有资金因此付出去。不过这批样本已经出现在真实收件箱里，说明攻击者在按读邮件 AI 的内容解析方式专门构造诈骗邮件，IT 安全负责人、Agent 管理员和财务应付团队需要在出事前把网关检测规则与最小权限边界配好。

### 读邮件的 Agent 只做摘要不发信，还会受影响吗？

就算关掉了对外发信权限，外部邮件里的异常文字仍可能干扰摘要输出，比如诱导模型在摘要里隐去异常发件地址提示，或者把伪造的高管催款标成加急待办事项。外部邮件和附件进入模型前依然要当成纯数据与系统指令分开存放并标明来源，财务人员看摘要办业务时也要点开原始邮件和合同验收单据逐项核对。

### 怎么发现邮件里的隐藏指令？

邮件里的隐藏指令通常用极小号、白色、零宽高的样式藏在正文底层，或者用不显示的 Unicode 标签字符编码，人眼和读屏软件都看不到。企业要在邮件进来时由安全网关或检测规则专门扫描不显示的元素、代码注释里写给 AI 的话以及不显示的 Unicode 字符；可以配置成查出异常后直接打标签、放进隔离区并通知 IT 安全核查，不交给 Agent 处理。
