服务台 Agent 替员工重置密码或解锁账号，动手修改前要把来访者的身份核实清楚。企业不能把改密权限直接交给对话模型自由判断，要把核验流程拆成系统可判定的信号比对。低风险请求按规则自动放行，高风险换绑交由人工专员把关。

## 接收重置请求：识别账号与工单状态

程序先从服务台入口抓取员工提交的工号或邮箱。后台接口去统一身份系统核查状态，确认账号是在职正常、临时锁定还是处于离职冻结阶段。对于已离职或被安全团队冻结的人员，程序直接停止响应并推送异常提醒。

系统识别出有效账号后，提取请求类型。员工是忘记密码、输错密码被锁，还是换手机收不到核对码，程序在界面上列出选项让员工选择。后台为会话生成独立追踪单号，把时间戳与网络接入节点写入单号底层。

服务台专员维护账号分类规则。普通办公账号、外包账号与核心特权账号，在系统内打上不同风险分级标签。分级标签决定了后续核对需要几个凭据，也决定了程序能不能在没有人工介入时直接调用接口。

## 调取在册信号：排查易被冒用的口头信息

程序向来访者索取核验凭据，比对在册底表。很多企业过去让人工客服问员工身份证号或入职日期，这些信息在工位上容易被打听到。比如有人拿到同事的工卡，就能直接报出工号和部门，程序单看这些静态文本辨别不出真伪。

系统调取不易被他人窥探的环境与硬件信号。程序读取员工发起对话时的设备指纹，比对移动设备管理系统里的登记记录。如果员工使用的是公司统一配发的在册办公电脑，且当前系统指纹与底表一致，程序判定该信号可信度较高。

员工要是从非受控设备发起求助，程序通过即时通讯工具向员工已登录的移动端推送确认卡片。后台给输错次数设上限，到了上限就中断对话，并给该员工的主管发预警。

## 低风险操作放行：调用接口发重置链接

核验信号吻合后，程序进入自动化办理环节。对于普通岗位的临时密码锁定，程序调用统一身份系统的解锁接口，清除错误尝试计数。普通密码重置，系统不在聊天框里发新密码，只往在册邮箱发一个很快过期的重置链接。

程序调用外部工具与核心接口时，要有明确策略约束。有关自动化调用的规则划分，可以参考 <NoteLink slug="agent-tool-call-auto-approval-rules">Agent 工具调用自动审批：哪些放行、哪些拦下</NoteLink>。对于符合白名单规则的常规解锁，系统自动完成接口请求并在屏幕上提示处理完毕。

运维主管负责定义自动放行的条件清单。运维人员根据历史安全事件，设定特定时段与特定网络区域的放行策略。一旦检测到某个部门短时间内集中出现重置请求，系统自动关闭放行通道，把后续请求导入人工队列。

## 高风险场景拦截：转交人工并拉主管确认

遇到修改多因素绑定设备或特权账号重置，程序直接暂停自动化修改。这类操作一旦被冒领，容易导致核心系统失控。程序将当前收集到的设备指纹、网络地址和对话摘要打包，转交给人工支持工程师。

在涉及权限变更和系统代操作时，底层身份机制直接关系到安全边界，具体权责边界见 <NoteLink slug="agent-acting-on-behalf-of-user">Agent 身份认证：替员工调系统用谁的权限</NoteLink>。人工工程师接单后，在后台调出员工入职时备案的信息，发起音视频核对。

高风险账号的密码重置还要拉入直属主管联合确认。系统向主管推送审批单，列明申请人、申请变更的事项与登录地点。只有主管在线完成数字签名，人工工程师才能在后台管理界面确认放行。

## 审计留痕建档：事后定期抽查调用轨迹

操作完成后，程序把全流程操作数据沉淀进审计日志。日志内容包括提单地址、设备识别串、每次校验凭据的提交结果、接口出入参报文以及人工审批的批注内容。日志文件写入独立的只读存储集群，防止私下修改或删除历史记录。

企业安全团队定期抽查重置日志。安全专员抽取特定数量的已办结工单，比对重置时间与员工门禁刷卡时间、考勤记录是否存在冲突。比如重置请求发生时员工门禁显示并未进入园区，且登录地在异地，这类记录会被标记为可疑个案单独复核。

安全专员根据抽查结果修正判定规则。如果发现某些新型话术试图绕过校验逻辑，工程师便在预处理模块补充拦截规则，调整凭据校验的置信度要求。

## 服务台 Agent：常见问题

### 为什么服务台 Agent 不能直接在聊天框里给员工发送重置后的新密码？

在聊天框里明文发送新密码存在泄漏风险。聊天窗口的内容容易被路过工位的人看到，也可能被截图外传，而且对话记录通常会保存在即时通讯系统的服务器上。稳妥的做法是向员工在册绑定的安全渠道发送单次有效的重置链接，或者生成临时口令并在首次登录后要求员工立即修改。

### 员工声称手机丢失且无法登录任何企业设备时，服务台 Agent 该怎么处理？

遇到所有在册设备和联系方式失效的情况，服务台 Agent 应当停止自动化流程，引导员工走线下人工通道。程序在界面上指引员工前往办公区的信息技术服务台，由现场工程师核验实体工卡与在职状态。现场工程师核实无误后，报经主管审批，在后台协助员工重新登记受信任设备。

### 遇到员工换手机或安全密钥丢失，服务台 Agent 能否独立完成身份验证？

服务台 Agent 无法在没有人工参与的情况下独立完成换绑时的身份验证。多因素认证凭据是保护企业内网的关键防线，一旦设备丢失，原本可信的环境信号已经中断。此时单凭线上的文本对话无法确认操作者是本人。这种场景下需要人工工程师接入，结合音视频交互、主管在线审批或者现场工卡查验，完成多重确认，才能重新绑定新的硬件凭证。
